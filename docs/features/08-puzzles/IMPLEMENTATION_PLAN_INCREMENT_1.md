# Feature 08 — Puzzles: Increment 1 Implementation Plan

## Scope

Increment 1 delivers the complete backend foundation for the puzzles feature: the Prisma schema migrations for `Puzzle` and `UserPuzzleAttempt`, the Lichess CSV seeder that populates the database with ~3.3M puzzles, and the read-only puzzle endpoints (`GET /puzzles/daily`, `GET /puzzles/:id`, `GET /puzzles`, `GET /puzzles/themes`). The daily puzzle is served from a Redis cache with a TTL computed as seconds until the next midnight UTC. No authentication is required for any endpoint in this increment. No attempt recording, rating updates, or SM-2 logic is included — those are Increment 2 and 3.

## Acceptance Criteria

- [ ] `prisma migrate dev` succeeds and creates the `Puzzle` and `UserPuzzleAttempt` tables with the GIN index on `themes`
- [ ] Running `npx ts-node src/puzzles/seeds/seed-puzzles.ts data/lichess_db_puzzle.csv` with a sample 100-row CSV completes without error and inserts all rows into the `Puzzle` table
- [ ] Re-running the seeder with the same CSV inserts 0 new rows (idempotent via `skipDuplicates: true`)
- [ ] `GET /puzzles/daily` returns 200 with `{ id, fen, moves, rating, themes, openingTags, isDaily: true }`
- [ ] `GET /puzzles/daily` returns the same puzzle on repeated calls within the same day (Redis cache hit)
- [ ] `GET /puzzles/daily` falls back to a random 1400–1600 rated puzzle when Redis is empty, without writing to Redis
- [ ] `GET /puzzles/:id` returns 200 with the correct puzzle fields for a known Lichess puzzle ID
- [ ] `GET /puzzles/:id` returns 404 for an unknown ID
- [ ] `GET /puzzles?theme=fork` returns only puzzles with `fork` in their `themes[]` array
- [ ] `GET /puzzles?minRating=1200&maxRating=1800` returns only puzzles within the rating range
- [ ] `GET /puzzles?page=2&limit=10` returns the correct paginated slice with correct `total`, `page`, `totalPages` values
- [ ] `GET /puzzles/themes` returns an array of `{ name, count }` objects covering all unique themes
- [ ] Unit tests in `src/puzzles/puzzles.service.spec.ts` pass for `getDailyPuzzle` (Redis hit, Redis miss, 503 fallback)

## Complexity

**M** — Moderate. The module, controller, service, and DTO scaffolding is straightforward NestJS boilerplate. The non-trivial parts are: (1) streaming the 900 MB CSV without loading it into memory, (2) the GIN index migration which requires a raw SQL block in Prisma since Prisma does not natively support `USING gin`, and (3) computing the correct Redis TTL to the next midnight UTC.
